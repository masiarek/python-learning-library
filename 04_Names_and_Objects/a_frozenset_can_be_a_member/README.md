# A frozenset can be a member

**Level:** 201 · for Python programmers

**One line:** Python has two set types for one reason: a `set` can change after it is stored, so it cannot be hashed, so it cannot be a member of a set or a key of a dict; `frozenset` is the same set with every changing method removed, and in exchange it can be all of those things.

## Why a second type

A set or a dict finds a member by its hash. If a member could change after it was filed, its hash would change with it, and the container would look in the wrong slot and fail to find it: the failure [Defining `__eq__` deletes `__hash__`](../../07_Classes_and_the_Data_Model/defining_eq_deletes_hash/README.md) shows for a custom class. Python prevents it for sets by refusing to hash a `set` at all. `frozenset` is the other half of that bargain: no `add`, `remove`, `update` or `|=` in place, and therefore a hash that depends only on the members.

What that buys is exactly what mathematics does with sets all the time: sets whose members are sets. The set of all subsets of {1, 2, 3} has eight members, each of them a set, and in Python it can only be written with frozensets. An unordered pair used as a dict key is the everyday version: `frozenset({'a', 'b'})` and `frozenset({'b', 'a'})` are one key.

## What the run shows

**Section 1** is the reason for the type: `{{1, 2}, {3}}` raises `TypeError`, and the same thing with frozensets works, including the eight-member set of all subsets.

**Section 2** is why a frozenset is a good key: equal frozensets hash equal whatever order they were built in, and a frozenset equals a set with the same members. Counting unordered pairs with frozenset keys merges each pair with its reverse.

**Section 3** is the cost. There is no `add`; `union` returns a new frozenset and leaves the old one alone; `copy()` returns the same object, since there is nothing to protect. And `t |= {2}` works, but not in place: with no `__ior__`, Python falls back to `t = t | {2}`, builds a new object and rebinds `t`, so another name for the old frozenset still sees `{1}`. That is the rule of [`+=` is not `+`](../plus_equals_is_not_plus/README.md), on a set. When a set and a frozenset are combined, the left operand decides the type of the result.

**Section 4** is the surprise. `{1, 2} in sets` works although `{1, 2}` is unhashable: set membership, `remove` and `discard` quietly treat a set argument as if it were frozen. A dict does not: `d[{1, 2}]` raises `TypeError`, and the key has to be frozen by hand.

## The Rust view

Rust has no frozenset, because it does not need one. Mutability belongs to the *binding*, `let` against `let mut`, not to the type, so one `HashSet` type serves both; and the borrow checker never hands out a `&mut` to an element stored in a set, so an ordinary member cannot change while it is filed. The exception is interior mutability: `Cell` and `RefCell` are not `Hash`, but they are `Ord`, so a `BTreeSet<Cell<i32>>` compiles, a member can be changed through `&`, and the set then fails to find a value it still holds. The compiler allows it; Clippy's `mutable_key_type` lint warns. What Rust does refuse is `HashSet<HashSet<T>>`: `HashSet` does not implement `Hash`. The ordered `BTreeSet` does, so a set of sets is written with `BTreeSet` as the element type, and collecting into a `BTreeSet` is Rust's "freeze" step. See the Rust library's [sets of sets ↗](https://masiarek.github.io/rust-learning-library/26_Collections/sets_of_sets/index.html).

## If you are coming from ABAP

ABAP has no frozenset and no read-only table type; read-only is a property of how a table is reached, not of the table. A set of sets is built by freezing each inner set into something that can be a key, for example a canonical sorted string, and storing that in a `HASHED` table `WITH UNIQUE KEY`, which is what `frozenset` does for you. Changing a key field of a line already in a sorted or hashed table is refused at runtime, the ABAP form of "a member must not change while it is filed". See the ABAP library's [sets of sets, and freezing a set ↗](https://masiarek.github.io/abap-learning-library/03_Topics/sets_in_abap/index.html#sets-of-sets-and-freezing-a-set). *(Not machine-checked — CI cannot run ABAP.)*
